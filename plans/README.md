## Findings considered and rejected

Recorded so they are not re-audited next run. Each was opened and read during vetting.

- **Static-handler path traversal (audit SECURITY-05)** — REJECTED (false positive).
  `apps/lattice_server/lib/lattice_server/static_handler.ex` resolves the served file via
  an **allowlist** (`file_for/1` maps only 6 fixed paths; everything else →
  `{:error, :not_found}`), so user input never reaches `Path.join`. The `..` check is
  redundant belt-and-suspenders on constant strings. No traversal is possible.
- **"Dead code: `MovableProcess`" (TECHDEBT-04)** — REJECTED. Actively exercised by
  `lattice_core_poc_test.exs`, `race_concurrency_test.exs`,
  `property_authority_invariant_test.exs`, and `demo/ad_preview.ex`. Not dead.
- **"Vestigial: `Lattice.Transport`" (TECHDEBT-05)** — REJECTED. Active `@behaviour` with
  three implementations (`web_socket.ex`, `demo/local_tab.ex`, `probe_tab.ex`) and ~42
  references. Not dead.
- **"Dead code: `Causality.ex`, delete it" (TECHDEBT-03)** — NOT PLANNED (not confidently
  dead). It has references outside its own module; if cleanup is wanted, investigate those
  first. Left as an investigate-item, not a delete-plan.
- **Atom exhaustion from the wire (SECURITY-01)** — REJECTED as a vuln. `Cap.normalize_op`
  uses `String.to_existing_atom` (safe) and WS ops come from server-side `grant_targets`
  config (`web_socket.ex:177`), not client input. Only `cap/session.ex:78` uses
  `String.to_atom`, on server-controlled session-transition names. A defensive switch to
  `to_existing_atom` there is a minor optional hardening, not a real exposure.
- **Resume token in-memory secret / node-local JTI (SECURITY-03, SECURITY-07)** — REJECTED.
  Documented single-node, in-memory POC behavior (`docs/threat_model_v2.md`,
  `docs/threat_model.md`). By design, not a finding.
- **Make Topology's disconnect-revoke synchronous (CORRECTNESS-02 fix)** — REJECTED. The
  `Task.start` in `topology.ex:206` is intentional: it avoids the documented
  Topology↔CapStore lock inversion (see `docs/lattice_poc_status.md`). The naive
  "make it synchronous" fix risks re-introducing the deadlock. (Using a supervised task is
  a possible low-value follow-up.)
- **`deliver_loop` O(n²) on pathological chains (PERF-06)** — NOT WORTH DOING. Only the
  out-of-order fallback path; designed delivery is dep-respecting. Optimize only if
  telemetry shows retry storms.
- **Graph.Snapshot O(n³) / audit-schema coupling (PERF-10, TECHDEBT-08)** — DEFERRED. v1
  demo/diagnostic code; POC-accepted. Not selected for a plan.
- **LiveOps god-module split (TECHDEBT-01), dual-audit unification (TECHDEBT-06),
  Cap v1/v2 coupling guard (TECHDEBT-07)** — DEFERRED. Real but L-effort architectural
  refactors of v1 demo code; not selected this round.
- **Duplicate web deps: `mint`/`websock_adapter` (DEPS-01, DEPS-03)** — DEFERRED. Pulled
  transitively only via `apps/lattice_carrier_spike`'s `web_socket_dist`; removing means
  touching the spike. Low value until the carrier work (plan 010) settles the web stack.
- **Cowboy/Playwright constraint lag (DEPS-04, DEPS-05)** — MINOR. `~> 2.12` vs locked
  2.14.2, Playwright `^1.53` vs 1.59. Mechanical bumps; do alongside other dep work.
- **Structured logging / telemetry (DX-06)** — DEFERRED. Real observability gap on the
  server, but MED value for a loopback POC; revisit when a real carrier (010) makes
  multi-node debugging matter.
